# 平台運費架構：核心組成與層級定義

在現行電商營運環境中，建構靈活且穩定的運費架構是平台生存的關鍵。「好賣家」與「超賣家」雙系統架構的複雜性源於系統開發的「技術債」——由於早期從 A 廠商（好賣版）過渡至 B 廠商（超級好賣）時，雙方的資料庫結構 (DB) 存在本質差異，架構差異直接反映在運費設定的三個層級中：

## 三層級架構定義

| 運費層級 | 定義與適用權限 | 系統適用性差異 |
| --- | --- | --- |
| **商品層級 (Product Level)** | 個別商品獨立設定運費（如設定 0 元免運）。 | **僅限好賣版**；超賣版因 B2C 結構限制，不開放單品設定。 |
| **賣場層級 (Shop Level)** | 針對「好賣版」多賣場特性（上限 200 個），設定特定賣場的滿額免運門檻（如 999 元）。 | 好賣版可進行多賣場差異化設定；超賣版採單一官網分類管理。 |
| **系統/平台層級 (System Level)** | 金物流設定中的全站預設運費（如常規 39 元或活動價 35 元），此為與物流商「日翊」結算的基礎。 | 雙系統通用，為最終保障之底線規則。 |
